## 1. What C0b and E0b are

- **Why.** Pack 9a ships C0's pot, lid and rack, flagged: their marker balls use `MK_R0` = 7 mm and a 5-9.5 mm window
  from the public-scan marker catalogue, and the lid and rack walls use 2.5 mm, a value that leaked from the scans.
  The audit found 16 scan-derived records and 71 records of unknown origin (16 of them suspect).
- **C0b** rebuilds the same method families on the same public episodes with every scan-derived and unknown item
  replaced by a GT-free value (section 3), picks one mesh per object by a pre-registered GT-free rule (section 5),
  scores each pick once (section 6) and runs C0's AUC guard (section 7).
- **Objects.** white_pot, white_pot_lid, plastic_dish_rack, blue_cup and, added by the orchestrator at ~17:10 UTC,
  **beige_cup** (the C1/T1 observed-point lathe with its separated-frame mask; section 10). The blue cup was held back
  from pack 9a because its selector was written after scoring; here its selection is pre-registered, so it can
  qualify.
- **E0b** applies the same replacements to E0's eval pipeline (section 9). The owner wants eval-built meshes; E0b
  meshes ship only for objects adopted in section 8.
- **Pack 10** is built 1 Nov ~14:00 UTC. This file fixes everything that decides which mesh goes into it.

## 3. Replacements (GT-free)

### 3.1 Principle
Every S and U record of `AUDIT.json` (87 records) gets exactly one replacement; the full table is section 3.9 and
`REPLACEMENTS.json` (generated by `scripts/prereg_table.py`, which fails if a record is missing). Classes:

| Class | n | Meaning |
|---|---|---|
| MK | 16 | the whole marker path is replaced by gmg `markers.py` (3.2) |
| TH | 8 | thickness chain (3.3) |
| LIB | 4 | library_v3 input removed (3.4) |
| A6 | 7 | a value frozen in gmg PREREG A.6 for the same meaning |
| A6B | 2 | gmg PREREG A.6b extent table, run x1 and x2 (3.6) |
| GEN | 5 | new generic value with a rule stated here (3.5-3.7) |
| KEEP | 40 | value unchanged, declared generic here (3.8) |
| NEVER | 2 | option exists, never selected |
| RULE | 2 | selection rule pre-registered here |
| INPUT | 1 | not a constant (tracks) |

Rules for choosing the class:
- **Scan-derived (S)** items are always replaced; no S value survives anywhere in a C0b or E0b build.
- **U-suspect** items are replaced by an own-observation estimate, a frozen gmg A.6 / A.6b value, or a new rule
  relative to an own-measured size. Two exceptions, disclosed: `--table_band` 8 mm (id 140, kept as 2 vote voxels;
  not a scan quantity) and `--tmin` 1.5 mm (id 121, the same number, now with the A.6 sensor origin).
- **Other U** items keep their value, re-declared generic with the rule in the table. This is a post hoc rationale:
  none of them has a recorded derivation, and none matches a scan number or was set in a scan-reading loop (audit
  section 2.2). The four that bound the C0 fit (`S0_MIN`, outline `s1 >= 0`, arch thickness clip, cup-floor 50
  points) are decided individually (ids 87, 58, 91).
- **Every replacement is an option.** With no new option the scripts behave exactly as now; C0 and E0 stay
  byte-reproducible (3.10).

### 3.2 Marker balls (MK; ids 8-15, 25-27, 71-73, 99, 101)
- **Detector:** `gmg/markers.py` `detect_episode(bundle, sigma, objects)` with its frozen settings (PREREG A.6 "ball
  detector" and "ball radius window" 1.5-12.5 mm, settings version 2). The run asserts
  `markers.SETTINGS_SHA256` equals the value at this commit. No radius prior: the window only bounds the search.
- **Input:** the object's C0b observed points (section 3.4), `own` = 0 for all points, `T` = the track length.
  `objects` = the episode's objects that C0b builds with `prim_potlid.py` or `prim_rack.py` (pot, lid, rack), so the
  pass-2 consensus radius is pooled over those objects of the episode. A thin wrapper may stand in for the gmg
  bundle; it passes the arrays unchanged and never changes a setting.
- **sigma:** the gmg A.2 estimator (`gmg/bundle.py _sigma(obs, frames)`, frames = the extraction frames
  `range(0, T, stride)`): route-A sheet from the even frames, median distance of odd-frame points to it, clamped to
  [0.5, 3] mm.
- **Attach:** `markers.attach(mesh, balls, obs)` on the finished body (+ handle bar or arch), per variant:
  - `fit` and `thick`: posts where `attach`'s stem rule finds observed points;
  - `nostem`: `attach(mesh, balls, obs=None)` (bare balls);
  - `nomk`: no balls.
- **No balls detected:** the mesh has no balls; it is still a candidate.
- **Rack joint:** the balls of the joint's episodes, mapped into the joint frame by the joint's own ICP alignment and
  the same final transform as the mesh, then the detector's frozen overlap suppression (centre distance < r_a + r_b:
  more votes stays). No new detection run on merged points.
- **What goes:** `MK_R0`, `MK_RMIN/MAX`, `MK_MIN`, `MK_DIAG`, `MK_RES`, `MK_GAP`, `STEM_MIN`, `STEM_R`, the free-fit
  acceptance, the re-cluster height, the stem rule, `MK_FREE_R`, `MK_SPREAD`, `marker_parts` and `in_basin`.
- **Why the family gains `nomk` for the pot and lid** (the rack family already has it): on the B7 dev files the frozen
  detector's balls were mostly false on the pot (ep2: none of the top 10 on a marker; ep27: 1 of the top 12 on a
  real ball, the rest on hands, rim and body) and the rack (ep31: peg tips, corners), and the lid's real balls came
  out with radii of 8.8-10.7 mm [M, dev, GT-free crop reading, `gmg/build/B7.md`]. Whether balls help is then decided
  by the GT-free pick, not by a person. `nomk` takes the slot of the dropped `tsdf` variant, so each family keeps
  four variants.

### 3.3 Thickness (TH; ids 16-20, 40, 58, 62, 87, 121, 128, 157, 158)
**The chain** (per object-episode, or per build for multi-episode builds):
1. Where the method measures the wall itself, it keeps that value. This is own-observation and unchanged:
   prim_potlid's median outer-inner distance over two-wall bins (C0 pot: 4.77 mm from 24 bins); lathe_obs's
   (C0 cup: 1.965 mm from 33 bins).
2. If the method cannot measure (fewer than 3 two-wall bins; the lid sheet; the rack wall and floor), use
   `gmg/thickness.py two_sided_measurements` on the same observed points. If it returns at least 200 finite
   measurements (the A.1 per-object minimum), use their median.
3. Otherwise use **t0_C0b**: the A.1 statistic (`thickness.aggregate`) on the C0b observed points of all 33 public
   object-episodes of `gmg/roster_public.json` (20 episodes), computed once on the public box before any candidate
   is built, written to `results/t0_c0b.json`, and frozen for E0b. A handle bar or lid strap without side evidence
   goes straight to t0_C0b (step 2 measures the whole object, not the part).
4. Clamp every value to [1.5, 8] mm (A.6 thickness floor, about 2 sigma; wall clip, two voxels).

What the chain means for each object:
- **Never used:** the 4 mm and 3 mm fallbacks, `T_MIN/T_MAX` 2-6 mm, `T_LID` and `T_WALL` 2.5 mm, the 1.5 / 2.5 /
  4.0 grid, and `thickness.py`'s own `FALLBACK` 2.5 mm (labelled scan-coincident in gmg A.1).
- **Not fittable:** if t0_C0b is not fittable by A.1 (fewer than 5 objects with 200 measurements), every build that
  needs step 3 fails; each failure is recorded and gives no candidate.
- **Expected [M, dev, on `obs_all`]:** the lid and the rack had 0 two-sided measurements on every public episode, and
  t0_dev was 5.36 mm. So the lid sheet and the rack wall will most likely be t0_C0b, about 5 mm, double C0's 2.5 mm.
- **Pot:** step 1 (C0: measured); fallback steps 2-3. `BAR_T0` = t0_C0b. Bar and arch thickness clip: [1.5, 8] mm.
- **Lid:** `T_LID` from steps 2-3. Arch strap thickness from side points clipped to [1.5, 8] mm (C0 sat on its old 3 mm
  floor); else t0_C0b.
- **Rack:** one `T` for the whole `prim_rack.py run` (it shares a floor depth over episodes): steps 2-3 on the pooled
  measurements of the run's episodes. `T` replaces every `T_WALL` term (floor plate, floor depth, cup wall, cup point
  classes, cavity), and `S0_MIN` = `T` (a lip is at least as wide as the wall it tops; id 87).
- **Lathe:** step 1; fallback steps 2-3; `--tmin` 1.5 mm (A.6 floor, the same number).
- **`thick` variant:** doubles the final thickness, as before.

### 3.4 Observed points (LIB; ids 133, 134, 160; KEEP 135, 138, 140, 142, 145, 149)
- **ROI:** a cube of half-side **0.30 m** about the track-frame origin (gmg A.6 crop; `recon_mesh` uses +-30 cm)
  replaces the library_v3 box (`--roi_cube 0.30`; no margin added).
  - [M] Pre-check on our own C0 points: the largest |coordinate| over all 33 `obs_all` object-episodes is 292.0 mm
    (rack), pot 263.7 mm. So the cube holds every point C0 observed.
  - **Guard:** if more than 0.1 % of a file's kept points lie within 8 mm (2 vote voxels) of a cube face, that file
    is rebuilt once at half-side 0.45 m (1.5 x, the factor of the A.6 crop guard), and the rebuilt file is used.
- **Co-objects** (`--others_pts NAME=NPZ`): two passes.
  - **Pass A** builds every tracked object of the episode with the C0b options and no co-object carving.
  - **Pass B** builds the final file. Its co-object surface is 20,000 random points (seed 0) of the co-object's
    pass-A points, posed by the co-object's track; this replaces the 20,000 surface samples of the library_v3 mesh.
  - `other_r` stays 12 mm (3 vote voxels).
  - [H] Mutual contamination (each object's pass-A points can hold the other's surface from frames where the two
    were static together) removes target samples only in those frames.
- **Unchanged obs_points settings:** stride 2, edge 20 mm, table band 8 mm (2 vote voxels; its suspect timing is
  disclosed in the audit; 8 mm is not a scan quantity), hand capsules, and the vote (4 mm voxel, hits >= 3, ratio
  >= 0.5, free 10 mm: the values gmg A.6 documents as generic).
- **[H] Risk:** the larger box admits static clutter within 30 cm while the object rests. The guard only handles
  clipping. Reported per file [M]: kept points vs C0's `obs_all` count.

### 3.5 Residual scale and pot and lid windows (A6, GEN; ids 6, 33, 45, 55, 117)
- **`APP_D`** (prim_potlid, 8 mm) and **`--app_d`** (lathe_obs, 4 mm) become **3 sigma**, with sigma the A.2 value of
  the observations the build uses (gmg A.6 grammar: "appendage points > 3 sigma outside the body"), so 1.5-9 mm.
  - For the merged blue-cup build, sigma is the median of its episodes' sigma.
  - In prim_rack, `APP_D` feeds only the replaced marker path, so it is unused (id 71).
- **Pot:**
  - polar origin `hO` = 0.5 x height (was 0.6);
  - handle cluster reach: P99 radius > 1.5 x rmax (was rmax + 60 mm).
- **Lid:**
  - arch = the largest residual cluster with >= 100 points and in-plane extent > 0.5 x r_edge (was 50 mm);
  - flange height band +-3 sigma (was +-6 mm).

### 3.6 Lid dome and flange windows (A6B; ids 47, 50)
gmg A.6b, with s = `autokit.parts.robust_scale` of the lid's voxel-downsampled observed points:
- dome window r in [E1, E2] = [0.05 s, 0.2 s] (was 15-35 mm);
- flange window r in [E3, E4] = [0.6 s, 1.2 s] (was 40-80 mm).

As A.6b prescribes ("every program is run with this table and with all extents doubled"), both tables are built:
`a6b1` (x1) and `a6b2` (x2: dome [0.1 s, 0.4 s], flange [1.2 s, 2.4 s]). Each table is a separate candidate set, and
the pick chooses between them. Other lid windows (tilt, `SURF_D`, residual radius, arch sampling, arch width) are
KEEP.

### 3.7 Lathe (GEN, NEVER; ids 107, 122, 131)
- **`TIE`** = 1.0: no tie-break, the axis with the best rotational consistency wins. This also applies to
  prim_potlid's `pot_axis`, which scores `lathe_obs.fit_axis`'s candidates. [M] For the C0 cup, TIE 1.1-2.0 picks the
  same axis (`scripts/tiecheck.py`).
- **Floor:** new choice `--floor base_t`: the floor top is base + t, always. The cap-point density rule (lower 40 %,
  > 200 points, < 10 mm layer), written 54 s after a scan-section plot, is not used.
  - Generic reason: a moulded vessel's floor is about one wall thick and rests on the support plane; sparse cap points
    are not a floor.
  - [M] On ep21 this equals C0's floor (`scripts/floorcheck.py`: the old rule also gave base + t there).
- **`--floor observed`** and prim_rack's `cup_upright()` are never selected; `PRIM_CUP_LEAN=1` is passed explicitly.

### 3.8 Values kept (KEEP, 40 records)
The value is unchanged and declared generic with the rule in the table (sample sizes, robust percentiles, multiples
of a voxel, shape-family defaults such as round pegs). Four of them bind in C0 and are named here so the risk is
visible:
- `JOINT_TOL` 1.25 (ep26 was 0.04 mm of fidelity from the cut in C0);
- `PEG_KAPPA` 1 (round pegs: the back of a peg is never seen);
- the cup-holder floor minimum of 50 points (43 in C0, so the tray floor is used);
- outline `s1 >= 0` (non-negative moulding draft; s1 = 0 in C0, so the sloped inner face is not identified).

## 5. The pick (GT-free; pre-registered for every object, the blue and beige cups included)

1. **Exclusions:**
   - raw mesh not watertight (trimesh, `process=True`);
   - kit `budget_mesh(path, 4096, 4096)` raises, or leaves more than 4096 faces or vertices;
   - no fidelity value.
2. **Fidelity:** `obs_fidelity.py OBS_1,...,OBS_k MESH` with defaults (trim 0.9, 300 k observed points, 200 k mesh
   samples, seed 0, no ICP; one mesh per process), on the C0b observed points of the object's set ALL (section 2).
   This is C0's selection formula.
3. **Pick:** the lowest `sum_mm`. Ties (equal to the printed 3 decimals) go to fewer raw faces, then to the label in
   byte order.
4. The pick is the object's **C0b mesh**. Before any scoring, it is committed to `C0b/meshes/` (if <= 10 MB, else the
   HF store) with its sha256, together with the fidelity table of all candidates.

Reported only, never deciding: fidelity per episode, C0's mesh and library_v3 fidelity on the same points,
`prim_rack.py run`'s own selection, the A.6b table each lid candidate used.

## 6. Scoring [D] (once per picked mesh)

- **Call:** one `mesh_metric.py run` per pick, at most 5 calls, with the default seeds (the eval seeds of the
  object's pairs, plus extra seeds 11, 22, ... up to at least 6 seeds). No 30-seed flip set.
  - The wrapper `scripts/score_c0b.py` refuses to score a sha1[:16] that `results/score_c0b.jsonl` already holds.
  - If a pick's sha1[:16] equals an existing scored record, that record is used and nothing is scored.
- **WIN per object:** all must hold:
  - `cdo_eval <= L - 0.02`;

    beige_cup) are excepted, as in gmg PREREG; their flips are reported.

## 10. The beige cup (orchestrator addition)

- **Method:** the same lathe pipeline as the blue cup with all section 3 options, on ep11, plus the T1
  separated-frame mask with its library_v3 surfaces replaced by our own points.
- **Rule M_sep(own):**
  - Let B be 20,000 random points (seed 0) of the beige cup's pass-A observed points, and Q_p the same for each other
    tracked object p of the episode (ep11: the blue cup).
  - Keep extraction frame t iff fewer than half of B, posed by the beige track at t, lie within 12 mm (`other_r`) of
    any Q_p posed by p's track at t.
  - The final beige file (pass B, with `--others_pts`) is filtered to the kept frames by its per-point `frame`, as T1's
    `mask_obs.py` did.
  - Hand-held frames are kept; hands are removed by the capsules, as in T1.
- **Too few separated frames:** an episode qualifies only with >= 10 kept frames **and** >= 20,000 masked points.
  These are generic minimums from gmg A.6: the B.2 reference minimum of 10 3-D-separated frames, and the 20,000
  owned-point low-coverage minimum.
  - Public ep11 not qualifying: the beige cup has no C0b candidate and is not adopted.
- **Eval (E0b):** the same rule on eval 8 (partner: white_pot) and eval 10 (partner: blue_cup), on the rebuilt eval
  points.
  - One eval episode does not qualify: it gives no candidate and is left out of ALL; the other episode's builds are
    the candidates.
  - Neither qualifies: ship the C0b public beige pick, if adopted.
  - Each case is recorded.
- **Scoring:** one mesh_metric scoring of the C0b beige pick; WIN by section 6's beige rule.
- **AUC guard:** single swap on ep11, with C0's base ep11 run reused under section 7's condition.
- **Open caveat (recorded, not resolved here):** eval 8 rollouts were tracked with library_v3x, and the pack keeps
  v3x's beige on eval 8. E0's eval-8 track input is the evperc track, whose job log says library_v3. So the beige
  object frame on eval 8 (v3 or v3x) is open. One beige mesh ships on both eval pairs, as in T1 / C1.

## 12. Hypotheses and known risks (stated before any build)

- **H-C0b [H]:** the scan-free rebuild keeps each object a WIN vs library_v3. Falsified per object by section 6.
- **[H] Cost of the cleanup:** with t0_C0b near 5 mm, the lid and rack lose a little against C0.
  - In C0's clean-up round, 4.0 mm gave lid 0.221 and rack 0.449 [D].
  - Prediction: each C0b pick within 0.03 cm of C0's CD-O. Falsified if any is worse by more than 0.03 cm. This is
    reported, not gating.
- **[H] Markers:** the pot's and rack's picks will be `nomk` or carry only a few balls, because B7 found mostly false
  balls on these objects [M, dev]. Falsified if a picked pot or rack mesh carries more than 5 balls. Reported only.
- **Known limits:**
  - **Fidelity is not CD-O.** On public data, Spearman was 0.85 over 32 pot candidates and 0.5 over 5 cup
    candidates; across rack episodes, fidelity did not track CD-O.
  - **Fidelity favours thin sheets.** The lid's unseen underside makes fidelity prefer thin sheets; the thickness here
    is not chosen by fidelity.
  - **In-sample twins.** Every candidate is built on some of its own AUC twins.
  - **One rack wall value.** The rack shares one `T` across episodes.
  - **ep0.** The lid track failed on ep0 (C0 caveat); the ep0 lid builds may fail.
  - **Static-object tables.** The rack and other resting objects depend on the table band (KEEP 8 mm) for their
    unseen bottom.
  - **Fewer changes than the audit list.** 40 values are kept with a post hoc generic rationale; this file does not
    claim they were derived.

## 13. Integrity

- **Ground truth:** construction and every choice in sections 3-5 and 9-10 read no scan, mocap, parquet pose,
  `*_align` file or library_v3 mesh. Scans and mocap are read only by `mesh_metric.py` (section 6) and
  `score_registered.py` (section 7), after this file and the public picks are pushed.
- **No tuning:** nothing is tuned on a score. Each distinct mesh is scored once. No threshold, candidate set, twin set
  or option changes after this commit. Failures are reported, not retried with changed settings; a crash may be
  re-run unchanged.
- **Public and eval kept apart:** eval results never feed back into the public stage.
- **Provenance:** the commit of the code used for every built and shipped mesh is recorded (submission provenance).
